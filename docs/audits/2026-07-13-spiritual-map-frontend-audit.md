# 阿崔的精神地图：前端与 UI/UX 审计

日期：2026-07-13

## 1. 审计范围

- 页面：首页书籍散落、影、音、浏览、关于。
- 交互：书影音切换、散落、抖动、整理、漩涡、筛选、拖拽、详情、分享、浏览搜索与组合筛选。
- 视口：1280 × 800、375 × 812，以及 Codex 内置预览的 523 × 600 窄窗口。
- 数据：Obsidian 只读构建、公开 JSON、封面副本与测试。
- 目标：保持 The Visible Shelf 为唯一视觉参考，不改变“艺术化个人书影音展示面”的产品方向。

## 2. 当前结论

当前版本已经具备正确的视觉骨架：暖纸背景、真实封面、散落重叠、低噪音导航、固定控制胶囊，以及书/影/音三个真实数据入口。102 本书、5 部电影、8 张专辑均已渲染，现有 17 个自动测试通过。

主要问题不在“视觉方向错误”，而在三个层面：

1. 操作状态之间没有统一规则，导致返回键、筛选、分享、拖拽和详情出现冲突。
2. 数据构建适合一次性生成，但还不适合长期持续更新。
3. 设计系统文档、CSS token、无障碍约束和实际代码没有完全对齐。

## 3. 已确认的优点

- 首页默认就是书籍散落状态，满足主页面方向。
- 书、影、音使用同一套视觉语言，但封面比例正确：书/影竖向、音乐 1:1。
- 散落、整理、漩涡布局均由确定性算法生成，可重复验证。
- 首页 102 本书全部进入 DOM；桌面首屏约 50 本，375px 手机首屏约 18 本。
- 浏览页搜索“塔勒布”能正确得到 3 本书。
- 当前页面无横向溢出。
- 书籍只公开完读年月；影和音没有日期字段。
- Obsidian 保持只读，网站无数据库、无后端、无自动同步依赖。

## 4. 问题清单与优化方向

### P1-01 媒体导航破坏浏览器返回逻辑

**证据**：从首页点击“影”后，地址变成 `/film.html`；按返回键直接回到 `about:blank`，而不是书籍首页。

**原因**：`app.js` 使用 `history.replaceState()`，但没有 `popstate` 处理。

**方案**：使用 `pushState` 写入媒体切换历史；新增 `popstate` 根据 pathname 恢复 `book/film/music`，同步页面标题、导航状态和数据。

**验收**：书 → 影 → 音后连续按返回，应依次回到影、书；刷新任一路径仍显示正确媒介。

### P1-02 键盘用户要经过 102 本书才能到达控制条

**证据**：首页共有 117 个可聚焦元素；“散落”位于第 107 个，“筛选”位于第 111 个，“浏览”位于第 113 个。

**影响**：键盘用户几乎无法实际操作布局和筛选。

**方案**：在 DOM 中将控制区放到作品区之前，保持视觉位置不变；增加“跳到陈列操作”和“跳到作品”链接；筛选后为不匹配作品设置 `inert`。

**验收**：从地址栏进入页面后，8 次 Tab 以内可到达所有主要操作；筛选“投资”后，Tab 不再进入被淡化的非投资书籍。

### P1-03 筛选与分享浮层会同时出现并重叠

**证据**：筛选面板范围为 y=625–722，分享选择条范围为 y=676–723，两者发生明显覆盖。

**原因**：筛选、选择、详情分别独立开关，没有互斥状态。

**方案**：建立唯一瞬时状态 `idle | filtering | picking | detail | poster`；进入一个状态前统一关闭其他状态；Escape 始终回到 `idle`。

**验收**：任意时刻最多出现一个浮层；筛选打开时点击分享，筛选先关闭再进入选择模式。

### P1-04 音乐分享海报把正方形专辑拉成长方形

**证据**：音乐分享预览中的 1:1 专辑封面被绘制为 280 × 420。

**原因**：海报代码对书、影、音都使用同一绘制尺寸。

**方案**：将海报几何计算提取到 `lib/poster.js`；音乐采用正方形槽位，书和电影采用竖向槽位；图片使用 cover 裁剪而不是拉伸。

**验收**：音乐海报五张图均为 1:1 且不变形；书和电影保持竖向；下载图和预览图一致。

### P1-05 数据加载失败时页面只剩空白

**证据**：主页 catch 只移除 `aria-busy`；浏览页的顶层 fetch 没有 catch，也没有检查 `response.ok`。

**方案**：新增共享 `loadMedia()`；统一处理 loading、HTTP 错误、JSON 错误和空数据；页面显示简短错误说明与“重新加载”操作。

**验收**：模拟 `media.json` 404 时，两个页面都出现可读错误，不出现空白陈列架或未处理 Promise。

### P1-06 书籍画布高度小于真实封面底边

**证据**：散落布局在 375/768/1280px 下分别溢出画布约 21/51/50px。

**原因**：画布高度只按行数估算，没有使用实际布局结果的最大底边。

**方案**：布局完成后，以 `max(top + renderedHeight)` 加底部安全区计算 stage 高度。

**验收**：所有模式和断点中 `maxBottom <= stageHeight - 32`；封面不进入 footer。

### P1-07 封面构建会留下旧文件

**证据**：`media.json` 引用 115 个封面，但 `public/covers` 有 230 个文件；目录总量 21MB，真实引用量约 9.99MB。

**方案**：构建成功后，根据新 JSON 的引用集合删除无引用的哈希封面；清理动作只允许作用于 `public/covers` 中符合哈希命名规则的文件。

**验收**：构建两次后封面数量保持不变；更换一个封面后旧哈希被移除；引用封面全部存在。

### P1-08 固定数量测试会阻止以后新增书影音

**证据**：测试把数量写死为 102/5/8，新增一条合法记录就会失败。

**方案**：测试改为校验 schema、类型非空、ID 唯一、引用封面存在和生成摘要一致；数量作为构建输出，不作为固定产品约束。

**验收**：新增一本书重新构建后测试仍通过，且页面显示 103。

### P2-01 总数量感知不足

**证据**：总数只在页面最底部；523 × 600 的常见内置预览首屏只显示约 12/102 本。

**方案**：在顶部媒介导航中低调显示当前总数，例如“书 102”；为 440–639px 增加四列密度档，避免整个范围一直使用三列。

**验收**：375px 首屏不少于 16 件、523px 首屏不少于 20 件、1280px 首屏不少于 45 件；总数无需滚到底部即可看到。

### P2-02 影和音首屏过于集中在顶部

**证据**：5 张电影海报和 8 张专辑基本形成单行，页面下半部大面积空白。

**方案**：为电影使用两层戏剧性对角构图，为音乐使用两行松散拼贴；保持相同纸面和控制逻辑，不引入新风格。

**验收**：电影与音乐首屏重心覆盖约 120–520px 高度范围；不遮挡品牌、导航和控制条。

### P2-03 手机触控目标不足 44px

**证据**：顶部“书/影/音”约 11 × 22px；底部按钮高度约 35px。

**方案**：链接和按钮设置最小 44 × 44px 点击区，视觉文字仍保持当前轻量尺寸。

**验收**：真实浏览器测量所有主要触控目标不小于 44 × 44px。

### P2-04 详情和拖拽的操作规则不直观

**证据**：单击只选择，双击才打开详情；移动端没有双击提示。拖拽没有移动阈值或 `pointercancel` 清理。

**方案**：hover/focus 显示信息签；单击/轻触打开详情；超过 6px 才进入拖拽并抑制随后的 click；处理 pointerup 和 pointercancel。

**验收**：轻触稳定打开详情；拖拽不会误开详情；触控取消后不会残留 `is-dragging`。

### P2-05 浏览页媒介与分类筛选不联动

**证据**：选择“影”后仍显示全部 22 个全局分类，包括投资、个人成长和 Pop。

**方案**：媒介变化时，按当前媒介重新生成分类选项并重置无效分类。

**验收**：选择“影”后只出现电影现有分类及正确计数；切回全部后恢复全局分类。

### P2-06 筛选淡化后仍保留全部键盘和读屏内容

**原因**：当前只切换 opacity。

**方案**：对不匹配对象同步 `inert` 和 `aria-hidden`；恢复全部时移除。

**验收**：视觉、Tab 顺序和读屏结果使用同一筛选集合。

### P2-07 操作反馈不足

**证据**：复制链接无成功/失败提示；筛选面板不能通过 Escape 关闭；数据加载没有过程提示。

**方案**：所有瞬时反馈进入一个 `aria-live` 状态区；复制成功显示“已复制”，失败给出可操作提示；Escape 统一关闭当前瞬时状态。

### P3-01 设计系统文档与 CSS 已发生漂移

**证据**：`DESIGN.md` 标题仍为“阿崔的书架”；文档 token 是 `--ink-muted/--paper-line`，代码使用 `--muted/--line`；CSS 中存在 47 处颜色、尺寸或层级硬编码，包含 8000/9999/10000 等层级值。

**方案**：先更新设计合同，再统一 token 命名、空间单位、控制尺寸、阴影和 z-index 层级；不改变已确认色彩和材质。

### P3-02 数据源路径暴露本机绝对路径

**方案**：默认使用 `os.homedir()` 推导 vault；允许 `OBSIDIAN_VAULT` 覆盖；README 提供一条可复制的更新命令。

### P3-03 数据构建缺少可见诊断和重复 ID 防护

**方案**：使用文件名生成稳定 ID；对重复 ID、缺封面和非法封面输出明确诊断；非空坏记录阻止覆盖上一份可用 JSON；空模板继续忽略。

### P3-04 文案和公开边界不一致

**证据**：关于页仍写“不保存日期”，但书籍已经公开完读年月。

**方案**：统一为“书籍只展示完读年月，影和音不展示日期”。

### P3-05 发布层还不完整

**现状**：浏览/关于页缺 description 和社交分享信息；没有 favicon、canonical、404 或部署前检查。

**方案**：在核心交互稳定后再补齐静态发布元信息；不在本轮引入统计、Cookie、后端或社交功能。

## 5. 明确不做

- 不迁移 React、Vue、Next.js 或其他框架。
- 不增加数据库、后端、账户、评论、评分或推荐。
- 不改变 The Visible Shelf 单一视觉方向。
- 不增加时间线、年度统计或复杂精神坐标。
- 不为了性能删除散落、整理、拖拽和分享等核心体验。
- 不在没有真实性能证据前引入图片处理依赖。
